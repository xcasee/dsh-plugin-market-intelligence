# 核心执行流程（core_workflow）

本文件是市场情报分析的标准作业流程。所有分析都按「意图解析 → 信源发现 → 情报检索 → 深入分析 → 交叉验证 → 双格式交付」推进。

## 一、标准七步

| 步骤 | 动作 | 工具 | 产出 |
|---|---|---|---|
| 1 意图解析 | 提取实体（中英别名）、时间窗口、可信度门槛、分析类型 | — | 检索计划 |
| 2 信源发现 | 按类别/地区/语言筛选可信信源 | `find_trusted_sources` | `source_ids` |
| 3 广域扫描 | 主力检索，确认主题全景 | `search_intelligence` | 情报条目 |
| 4 维度深挖 | 按分析维度分别检索（见 `market_workflow.md`） | `search_intelligence` ×N | 分维度证据 |
| 5 趋势/聚合 | 量化热度与信源分布 | `analyze_trend` / `aggregate_by_source` | 趋势与信源画像 |
| 6 交叉验证 | 关键数字用精确短语多源复核 | `search_intelligence`（`"..."` + min_tscore≥0.7） | 已核验结论 |
| 7 交付 | Markdown 摘要 + HTML 报告 | — | 双格式产出 |

**参数缺省约定**：时间窗口默认 30 天（趋势 90 天、深度 180 天）；可信度默认 ≥0.6（关键决策 ≥0.8）。缺关键参数先向用户追问一次，不要编造。

## 二、T-Score 与 ABCD 分级

T-Score 是平台对每条情报/每个信源的 0–1 可信度评分，融合信源权威度预设与内容特征。分级与使用纪律：

| T-Score | 等级 | 标识 | 使用纪律 |
|---|---|---|---|
| ≥ 0.8 | A | 🟢 | 可直接作为决策依据 |
| 0.6–0.8 | B | 🟡 | 结合上下文使用 |
| 0.4–0.6 | C | 🔴 | 仅作信号，必须交叉验证 |
| < 0.4 | D | ⚪ | 视为传言，不作事实陈述 |

**ABCD 信源分级**：A=通讯社/官方（路透、彭博、新华社、官方公告、监管文件）；B=主流权威（TechCrunch、36氪、华尔街日报）；C=垂直媒体/博客；D=UGC/论坛。

**规范**：
- 每条引用都带 T-Score + 信源名 + 日期
- 关键结论若主要依赖 <0.8，必须显式提示「建议独立验证」
- 报告中区分「数据事实」（工具返回）与「分析推断」（你的判读）

## 三、意图决策树

```
用户输入
  ├─ 趋势/变化/走势/峰值 → analyze_trend (+ search_intelligence)
  ├─ 对比/哪些媒体/来源分布 → aggregate_by_source (+ search_intelligence)
  ├─ 找信源/有哪些来源 → find_trusted_sources
  ├─ 概念级/跨语种/表达模糊 → search_with_cvc → semantic_search
  └─ 默认 → find_trusted_sources → search_intelligence → (按需追加)
```

## 四、证据组织纪律

1. **一结论多证据**：每个关键结论至少 1 条 A/B 级证据；规模、份额、增速等数字尽量 2 个独立信源。
2. **口径标注**：区分「官方统计 / 行研估算 / 媒体报道口径」，例如份额数据须注明「报道口径，非出货统计」。
3. **样本量披露**：每个章节开头写明样本量 N、时间窗口、检索词，避免以偏概全。
4. **盲区提示**：说明哪些维度证据不足（写 ⬜ 或「数据缺失」），不要用估算冒充事实。

## 五、错误处理

见 `SKILL.md` 第七节。要点：`AUTH_REQUIRED` → 引导取密钥并**新开对话**；`RATE_LIMITED` → 降并发重试；空结果 → 放宽条件；语义无结果 → 先归集语料。
